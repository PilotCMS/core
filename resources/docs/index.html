Pilot CMS

Installation

This guide documents how to install the Pilot CMS application, connect a Laravel frontend with the pilot/laravel package, and enable Incontext editing for iframe preview workflows. It is written in the same practical structure as Laravel's documentation: concepts first, exact commands next, then configuration, verification, and troubleshooting.

CMS Application

The authoring application where editors manage spaces, content, block types, assets, datasources, users, settings, previews, and publishing workflow.

Laravel Connector

The frontend adapter that reads Pilot content, resolves assets, renders Blade views, exposes preview routes, and ships editor bridge views.

Incontext

The editing layer that marks fields and blocks in rendered pages so the CMS can inspect and update content while an editor is previewing a page.

Overview

Pilot is a Laravel-based, Storyblok-style CMS. The CMS owns editorial data. A Laravel frontend, either the CMS application itself or a separate Laravel site, renders that data using Blade components. The connector package provides the integration surface between those two systems.

The default development setup in this repository keeps everything in one application: content models, admin UI, public theme rendering, REST delivery, GraphQL delivery, preview routes, and the package source for the Laravel connector. A production setup may keep the CMS and the website separate, with the website depending on pilot/laravel.

Source of truth.

The connector package in this repository is located at packages/pilot-laravel. Its package name is pilot/laravel, and its service provider is Pilot\Laravel\PilotServiceProvider.

Architecture at a glance

Layer Responsibility Primary files
CMS application Stores content, block schemas, assets, roles, settings, preview targets, revisions, and publishing metadata. app/Livewire/Admin, app/Models, database/migrations, routes/admin.php
Delivery API Provides published and protected draft content for headless consumers. routes/api.php, app/Http/Controllers/Api, graphql/schema.graphql
Theme rendering Maps normalized block payloads to Blade views. resources/views/themes/{theme}, config/cms.php
Laravel connector Installs reusable helpers, config, views, preview routes, and Incontext endpoints in a Laravel frontend. packages/pilot-laravel

System Requirements

Install the CMS on a machine that can run a modern Laravel 12 application. This repository's dependency lock currently requires a PHP runtime newer than the system PHP found on many Macs, so use the same PHP binary for Composer, Artisan, queues, and tests.

Dependency Requirement Notes
PHP 8.4.1 or newer; PHP 8.5 works for this repository The project instructions identify PHP 8.5.2. Herd users can use the path to a supported PHP binary.
Composer 2.x Use it with the same PHP version used by Artisan.
Node.js and npm Current LTS recommended Needed for Vite, Tailwind CSS v4, and frontend assets.
Database MySQL, MariaDB, PostgreSQL, or SQLite MySQL is the opinionated local default; SQLite remains available as an explicit opt-in.
Web server Herd, Valet, Sail, nginx, Apache, or Caddy Public entry point must be public/index.php.
Storage Local disk or S3-compatible disk Assets are stored through Laravel's filesystem.

Recommended local PHP command

If you are using Herd and the shell's default PHP is too old, call Artisan through the Herd binary explicitly: 

<path-to-php> artisan about

If your Composer command is also using the wrong PHP version, run Composer with the correct binary: 

<path-to-php> composer install

Installation Paths

There are two supported ways to install Pilot for development and implementation work. Choose the path that matches your deployment model.

Single Laravel app

Use this repository as both the CMS and the public rendering app. This is fastest for local development and theme work.

CMS plus Laravel site

Run Pilot as the CMS and install pilot/laravel into a separate Laravel frontend.

Headless frontend

Use REST or GraphQL APIs from any frontend. Install the Laravel connector only when the frontend is Laravel.

Do not mix runtime versions.

The most common local installation failure is installing dependencies with one PHP version and running Artisan with another. Keep Composer, Artisan, queue workers, schedulers, and tests on the same PHP binary.

Install Pilot CMS

This section installs the CMS application itself. It assumes you have cloned the repository and are working from the project root.

  1. Install PHP dependencies

    Install the Composer dependencies with the PHP runtime that satisfies the lock file.

    composer install

    When the shell PHP is older than the project requires, use the PHP binary explicitly:

    <path-to-php> composer install

  2. Install JavaScript dependencies

    Install the Vite, Tailwind, and frontend tooling dependencies.

    npm install

  3. Create the environment file

    Copy the example environment file if one does not already exist, then generate the app key.

    cp .env.example .env
php artisan key:generate

    If you are using Herd's PHP binary:

    cp .env.example .env
<path-to-php> artisan key:generate

  4. Configure the database

    Pilot defaults to MySQL. Start MySQL, create an empty pilot database, and adjust the standard Laravel credentials in .env when needed. 

    DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=pilot
DB_USERNAME=root
DB_PASSWORD=

    SQLite remains available as an explicit alternative:

    touch database/database.sqlite
    DB_CONNECTION=sqlite
DB_DATABASE=<path-to-database>/database.sqlite

  5. Configure Pilot CMS defaults

    The CMS application reads public rendering defaults from config/cms.php. Set the default space and home slug so the public routes can resolve the correct page. 

    CMS_DEFAULT_SPACE=main
CMS_HOME_SLUG=home
CMS_DELIVERY_SOURCE=mysql
CMS_THEME=default

    Some historical notes in the repository use PILOT_DEFAULT_SPACE and PILOT_HOME_SLUG. Those names are used by the connector package. For the CMS application's own config/cms.php, use the CMS_ keys.

  6. Run the interactive installer

    Create the schema with Laravel migrations, seed Pilot's roles and block types, and create the first administrator account.

    php artisan pilot:install

    The installer asks for the administrator's name, email address, and password. No default user credentials are seeded. In production, allow migrations with --force:

    php artisan pilot:install --force

  7. Verify the account and default space

    The installer assigns the new account the Admin role and initializes the main space and starter content under that account.

  8. Link public storage

    The CMS asset manager stores files through Laravel's filesystem. For local public storage, create the standard storage symlink. 

    php artisan storage:link

  9. Build frontend assets

    Build static assets for production or run Vite during development.

    npm run build

    For active development:

    npm run dev

  10. Start the application

    Run the full development stack or serve the app with your local web server.

    composer run dev

    For a single-process Laravel server:

    php artisan serve

One-command setup

The root composer.json includes a setup script that installs PHP dependencies, creates .env, generates the app key, runs the interactive Pilot installer, links public storage, installs npm packages, and builds assets. Create and configure the MySQL database first; the command will prompt for the administrator account: 

composer run setup

Use the manual steps instead when you need to choose a different database, tune storage, or confirm each phase independently.

First Login

Open the CMS dashboard and sign in with the administrator account created by php artisan pilot:install. No default user accounts or passwords are installed. Create additional Editor, Author, and Viewer accounts from user management as needed.

The main admin dashboard is available at /admin/dashboard. Common sections include /admin/content, /admin/assets, /admin/datasources, /admin/users, and /admin/settings.

Install Laravel Connector

Install the connector into a Laravel application that should render Pilot content. In this repository, the connector is developed locally from packages/pilot-laravel. In a separate Laravel frontend, install the published Composer package once available.

Local path repository installation

During local development, add the connector as a path repository from the frontend application's composer.json: 

{
    "repositories": [
        {
            "type": "path",
            "url": "../Pilot/packages/pilot-laravel",
            "options": {
                "symlink": true
            }
        }
    ],
    "require": {
        "pilot/laravel": "*"
    }
}

Then install it:

composer update pilot/laravel

Published package installation

When the package is published to a Composer registry, install it like any Laravel package: 

composer require pilot/laravel

Package auto-discovery

The connector registers itself through Laravel package auto-discovery. Its provider merges config/pilot.php, loads package views, registers preview and Incontext routes when enabled, and binds a singleton manager as pilot. 

{
    "extra": {
        "laravel": {
            "providers": [
                "Pilot\\Laravel\\PilotServiceProvider"
            ],
            "aliases": {
                "Pilot": "Pilot\\Laravel\\Facades\\Pilot"
            }
        }
    }
}

Publish configuration and views

Publish the connector config when the frontend app needs to override defaults: 

php artisan vendor:publish --tag=pilot-config

Publish connector views only when you need to customize the package bridge or preview markup: 

php artisan vendor:publish --tag=pilot-views

Configure Connector

The connector reads configuration from config/pilot.php. These values define the default content space, locale, CMS origin, asset origin, page views, block views, preview routes, and Incontext routes. 

PILOT_DEFAULT_SPACE=website
PILOT_HOME_SLUG=home
PILOT_DEFAULT_LOCALE=en
PILOT_CMS_URL=https://cms.example.com
PILOT_ASSET_URL=https://cms.example.com

PILOT_PAGE_VIEW=page
PILOT_BLOCKS_VIEW=blocks

PILOT_EDITOR_BRIDGE_ENABLED=true
PILOT_LIVE_PREVIEW_ENABLED=true
PILOT_LIVE_PREVIEW_ROOT="[data-pilot-live-root]"

PILOT_IN_CONTEXT_ENABLED=true
PILOT_IN_CONTEXT_PATH=_pilot/in-context

PILOT_PREVIEW_ROUTES=true
PILOT_PREVIEW_PATH=_pilot/preview
PILOT_PREVIEW_SECRET="${APP_KEY}"
PILOT_PREVIEW_EXPIRES_MINUTES=60
Key Purpose
PILOT_DEFAULT_SPACE The content space slug used by default queries and renderers.
PILOT_HOME_SLUG The slug treated as the homepage when resolving root content.
PILOT_DEFAULT_LOCALE The locale used when localizing block field arrays.
PILOT_CMS_URL The CMS origin used when the frontend needs to call back to Pilot.
PILOT_ASSET_URL The base URL for relative asset paths. Defaults to PILOT_CMS_URL.
PILOT_PREVIEW_SECRET The HMAC secret for package preview and Incontext requests. Use a strong shared secret in split deployments.

Render Content

The connector exposes a manager through the Pilot facade and the pilot container binding. It provides access to content queries, rendering, and preview URL generation.

Basic controller

A simple Laravel frontend controller can resolve content by slug, then return a page view. The exact query methods depend on the delivery implementation wired behind the connector, but the view contract should stay stable: pass normalized content and render blocks through a dedicated block partial. 

<?php

namespace App\Http\Controllers;

use Illuminate\Contracts\View\View;
use Illuminate\Http\Request;
use Pilot\Laravel\Facades\Pilot;

class PageController
{
    public function show(Request $request, string $slug = 'home'): View
    {
        $content = Pilot::content()
            ->space(config('pilot.default_space'))
            ->locale($request->getLocale())
            ->slug($slug)
            ->firstOrFail();

        return view(config('pilot.views.page'), [
            'content' => $content,
            'blocks' => $content['content']['body'] ?? [],
        ]);
    }
}

Blade page view

Keep the page view small. It should set up the layout, expose a live preview root, and delegate block rendering to a block partial. 

<x-layouts.marketing>
    <main data-pilot-live-root>
        @include(config('pilot.views.blocks'), [
            'blocks' => $blocks,
        ])
    </main>
</x-layouts.marketing>

Block partial

Block rendering should be deterministic and tolerant of missing views. Missing block views should render a fallback instead of breaking the whole page. 

@foreach ($blocks as $block)
    @php
        $component = $block['component'] ?? $block['type'] ?? 'fallback';
        $view = "blocks.{$component}";
    @endphp

    @includeIf($view, ['block' => $block])
@endforeach

Block view

Read display content from $block['data']. Read nested content from $block['children']. Keep block keys stable because they are a public contract between the CMS and the website. 

@php
    $title = $block['data']['title'] ?? '';
    $subtitle = $block['data']['subtitle'] ?? '';
@endphp

<section class="mx-auto max-w-6xl px-6 py-20">
    <h1 class="text-5xl font-bold">{{ $title }}</h1>

    @if ($subtitle !== '')
        <p class="mt-6 text-lg text-slate-600">{{ $subtitle }}</p>
    @endif
</section>

Asset Handling

The connector registers helper functions for turning Pilot asset paths into frontend URLs. Use them instead of manually concatenating CMS URLs in Blade views.

Helper Use
pilotAsset($path) Returns an absolute URL for a Pilot asset path.
pilotAssets($path) Alias of pilotAsset.
pilotAssetFormatted($path, $data, $field) Returns URL, source, focal point, object position, and inline style helpers.
pilotAssetsFormatted($path, $data, $field) Alias of pilotAssetFormatted. 
@php
    $image = pilotAssetFormatted(
        $block['data']['image'] ?? null,
        $block['data'] ?? [],
        'image'
    );
@endphp

@if ($image['url'] !== '')
    <img
        src="{{ $image['url'] }}"
        alt="{{ $block['data']['alt'] ?? '' }}"
        style="{{ $image['object_position_style'] }}"
    >
@endif

Preview Links

The connector can register signed preview routes under _pilot/preview. The route is controlled by PILOT_PREVIEW_ROUTES and PILOT_PREVIEW_PATH. 

GET /_pilot/preview/{content}

Preview requests are protected by EnsureValidPilotPreview. The middleware validates the preview signature, expiration, and configured secret. For split deployments, configure the same preview secret in the CMS and frontend.

Preview environment

PILOT_PREVIEW_ROUTES=true
PILOT_PREVIEW_PATH=_pilot/preview
PILOT_PREVIEW_SECRET=base64-or-random-shared-secret
PILOT_PREVIEW_EXPIRES_MINUTES=60

Preview iframe headers

Client-facing preview targets must allow the CMS editor origin to embed preview pages in an iframe. If the frontend returns X-Frame-Options: SAMEORIGIN, browsers will block cross-origin editor previews before Pilot or Livewire can load the frame.

Remove X-Frame-Options from previewable responses, especially /_pilot/preview/*, and prefer a Content-Security-Policy frame-ancestors allow-list: 

add_header Content-Security-Policy "frame-ancestors 'self' https://cms.example.com" always;

Use the exact CMS editor origin, including scheme and port when needed. Do not use a wildcard. After changing Forge or nginx headers, reload nginx and confirm the preview response no longer includes X-Frame-Options: SAMEORIGIN.

Install Incontext

Incontext is the package feature that makes rendered pages editable inside the CMS preview. It does not replace the CMS editor. It adds field and block metadata to the frontend so the editor can select blocks, fetch block data, update fields, and sync content state.

  1. Install and configure the connector

    Incontext ships with pilot/laravel. Install the connector first, then publish config/pilot.php if the frontend needs local overrides. 

    composer require pilot/laravel
php artisan vendor:publish --tag=pilot-config

  2. Enable Incontext routes

    Keep connector preview routes enabled unless the frontend registers custom routes. The package registers Incontext endpoints beneath PILOT_IN_CONTEXT_PATH. 

    PILOT_PREVIEW_ROUTES=true
PILOT_IN_CONTEXT_ENABLED=true
PILOT_IN_CONTEXT_PATH=_pilot/in-context

  3. Configure preview trust

    Incontext write requests are allowed for authenticated users. Unauthenticated preview requests must include a valid content id, expiration, and HMAC signature. Configure a shared preview secret in split CMS/frontend deployments. 

    PILOT_PREVIEW_SECRET=change-me-to-a-shared-secret

  4. Add a live preview root

    The editor bridge replaces the element matching PILOT_LIVE_PREVIEW_ROOT when live preview renders new HTML. The default selector is [data-pilot-live-root]. 

    <main data-pilot-live-root>
    @include('blocks', ['blocks' => $blocks])
</main>

  5. Annotate editable fields

    Add Incontext attributes to the smallest meaningful editable element. For a text field, apply the attributes to the element that displays the text. 

    <h1 {!! app(\Pilot\Laravel\Support\InContext::class)->field($block, 'title') !!}>
    {{ $block['data']['title'] ?? '' }}
</h1>

  6. Open the page in preview mode

    Incontext metadata is emitted in editor contexts. Add pilot_editor=1, editor=1, or pilot_preview=1 to a preview URL, or open the page from the CMS editor iframe. 

    https://site.example.com/about?pilot_editor=1
Expected result.

In preview mode, editable fields include data-pilot-editable="field", data-pilot-block-id, data-pilot-field, and data-pilot-field-type. Normal public requests do not include those attributes unless Incontext is explicitly enabled for the request.

Editable Markup

Incontext annotations should be precise and stable. Mark the field, not the entire section, when the editor is changing only one value. Mark a block wrapper when the editor needs block selection, movement, or nested block awareness.

Text fields

<h2 {!! app(\Pilot\Laravel\Support\InContext::class)->field($block, 'headline', 'text') !!}>
    {{ $block['data']['headline'] ?? '' }}
</h2>

Rich text fields

<div {!! app(\Pilot\Laravel\Support\InContext::class)->field($block, 'content', 'richtext') !!}>
    {!! $block['data']['content'] ?? '' !!}
</div>

Image fields

<figure {!! app(\Pilot\Laravel\Support\InContext::class)->field($block, 'image', 'asset') !!}>
    <img src="{{ pilotAsset($block['data']['image'] ?? null) }}" alt="{{ $block['data']['alt'] ?? '' }}">
</figure>

Manual attribute output

The helper returns an HtmlString, so it should be printed unescaped with {!! !!}. It returns an empty string when Incontext is disabled or the block does not have an id.

Incontext API

When package routes are enabled, the connector registers the following endpoints. The path prefix defaults to _pilot/in-context.

Method Endpoint Purpose
GET /_pilot/in-context/contents/{content}/sync Returns content metadata, sync key, and server time for preview synchronization.
GET /_pilot/in-context/blocks/{block} Returns localized block data, raw data, schema, and parent content metadata.
PATCH /_pilot/in-context/blocks/{block} Updates one or more schema-defined block fields.

Update payload

Updates accept a fields object and optional locale. Fields not present in the block type schema are ignored. Translatable fields are written into the selected locale. 

{
    "locale": "en",
    "fields": {
        "title": "Updated headline",
        "subtitle": "Updated supporting copy"
    }
}

Successful update response

{
    "updated": true,
    "block": {
        "id": 123,
        "type": "hero",
        "name": "Hero",
        "updatedAt": "2026-06-10T18:25:00.000000Z",
        "data": {
            "title": "Updated headline"
        },
        "schema": {
            "fields": []
        },
        "content": {
            "id": 45,
            "name": "Home",
            "slug": "home",
            "updatedAt": "2026-06-10T18:25:00.000000Z",
            "syncKey": "..."
        }
    }
}

Security Model

Pilot separates public rendering from editing. Public pages should render only published content. Draft content, preview updates, and Incontext writes require authentication or a valid signed preview request.

Incontext request authorization

The package controller allows Incontext requests when either condition is true:

  • The current Laravel request has an authenticated user.
  • The request includes the correct content id, a future expiration timestamp, and a valid HMAC signature.

Preview signature inputs

The signature is based on {contentId}|{expiresAt} and uses pilot.preview.secret. If no preview secret is configured, the package falls back to app.key. In production split deployments, configure an explicit shared secret instead of relying on app keys matching. 

$expected = hash_hmac(
    'sha256',
    "{$contentId}|{$expiresAt}",
    config('pilot.preview.secret') ?: config('app.key')
);

Public page rule

Public routes should only select content where type = page, status = published, published_at is not null, and the slug matches the route. Do not expose draft content on public routes without a signed preview path.

Production Checklist

Use this checklist before launching either the CMS or a Laravel frontend that consumes Pilot.

CMS application

  • Set APP_ENV=production and APP_DEBUG=false.
  • Set a trusted APP_URL that matches the public CMS URL.
  • Use a persistent database, not a disposable local SQLite file.
  • Run php artisan migrate --force during deployment.
  • Run php artisan storage:link when using the public local disk.
  • Configure S3 or another persistent disk for uploaded assets when deploying across multiple servers.
  • Run queue workers for scheduled publishing, asset processing, and any future async work.
  • Run the Laravel scheduler if scheduled content publishing is enabled.
  • Build assets with npm run build.
  • Cache configuration, routes, events, and views after all environment variables are set.

Laravel frontend connector

  • Set PILOT_CMS_URL to the CMS origin.
  • Set PILOT_ASSET_URL if assets are served from a CDN or storage domain.
  • Set PILOT_DEFAULT_SPACE, PILOT_HOME_SLUG, and PILOT_DEFAULT_LOCALE.
  • Set an explicit PILOT_PREVIEW_SECRET shared with the CMS.
  • Keep PILOT_PREVIEW_ROUTES=true unless custom preview routes are registered.
  • Keep PILOT_IN_CONTEXT_ENABLED=true only for sites that support editor preview workflows.
  • Confirm the frontend's CSP allows the CMS editor to embed the preview origin when iframe preview is required.

Security

  • Rotate seeded passwords before exposing any non-local environment.
  • Restrict admin access to trusted users.
  • Use HTTPS for CMS and frontend origins.
  • Do not expose draft API responses without Sanctum auth or a signed preview route.
  • Do not log preview secrets or signed preview URLs in long-lived public logs.

Troubleshooting

Composer says the PHP platform is too old

Your shell is using an older PHP than the dependencies require. Run Composer and Artisan with the same supported PHP binary. 

<path-to-php> artisan about

The CMS loads but styles are missing

Build frontend assets or run the Vite dev server. In production, deploy the generated public/build assets. 

npm run build

Uploaded assets return 404

Confirm the storage disk is configured and the public storage symlink exists. 

php artisan storage:link

Large asset uploads fail with 413

Increase the web server upload limit. This repository includes a helper script for Herd/nginx local development: 

chmod +x fix-upload-limit.sh
./fix-upload-limit.sh

Preview returns 403

Check that the preview link has not expired, the content id matches the signed content id, and PILOT_PREVIEW_SECRET matches between the signer and the frontend.

Preview iframe is refused

If the browser reports that the preview site refused to display in a frame because it set X-Frame-Options to sameorigin, remove that header from previewable frontend responses and allow the CMS editor origin with Content-Security-Policy: frame-ancestors.

Incontext attributes are missing

Confirm PILOT_IN_CONTEXT_ENABLED=true and open the page in an editor context by using ?pilot_editor=1, ?editor=1, ?pilot_preview=1, an authenticated session, or a CMS editor referer.

Incontext updates ignore a field

The update endpoint only writes fields that exist in the block type schema. Confirm the field key in the rendered markup exactly matches the schema key.

Relative asset URLs point at the wrong host

Set PILOT_ASSET_URL. It defaults to PILOT_CMS_URL, which may not be correct when assets are served from a CDN.
